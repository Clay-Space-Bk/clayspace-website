# Clay Space — website

Marketing and commerce site for Clay Space Ceramic Center, 275 Calyer Street,
Greenpoint, Brooklyn. Next.js 16 App Router, **static export**. Runs on
**:3007**.

```bash
npm install && npm run dev
```

## Hard constraints

- **`output: "export"`.** No dynamic segments without `generateStaticParams`,
  no route handlers, no server actions, no `next/headers`. Adding one fails the
  build — that is the point.
- **`images: { unoptimized: true }`** is required; the export fails without it.
- **Never commit `.env`.** The website receives no database credentials and no
  auth secret, ever. Studio ONE holds those and stays local.
- **Never force-push `main`.** It is the only copy of the project history.
- **Brand orange is `#EE552B`**, not `#F95C20`. Prefer `var(--cs-*)` over hex.

## Traps that have already cost time

- **`next build` and `next dev` share `.next/`.** Stop the dev server before
  building or the directory is corrupted.
- **The nav rail is the hydration canary.** After any change to the export or
  its paths, open and close it. Nothing else fails as quietly — the page still
  renders, the console stays clean, and interactivity is simply gone.
- **Never rewrite paths inside `self.__next_f.push(...)`.** That inline flight
  data carries absolute `/_next/` URLs; rewriting them kills hydration silently.
- **Five nav icons are built at runtime** from `/assets/img/ceramic-icons/${slug}.svg`.
  No static analysis sees them. Exclude `ceramic-icons/` from any unused-asset
  sweep.
- **`next-env.d.ts` is generated by the build** and declares the module types
  for image imports. `tsc` before a build fails with TS2307 on every image in
  `src/data`. CI builds first for this reason.
- **`next start` does not work** with a static export. `npm start` serves
  `out/` on `:3008`.
- **Module reachability does not prove data is live.** `animationConfig.ts`
  keyed 41 routes when 3 exist; `blogData` held 43 entries for the 3 that
  render. Check what *selects* the data, not just what imports the file.
- **A root-relative build and a `PAGES_BASE_PATH` build are different**, each
  broken in the other's context. `basePath` does not rewrite hardcoded
  `/assets/` strings — those need a post-build pass.
- **`clayspace-light` on `<html>` and the selector in `_light.scss` must
  match.** Rename both or neither.

## Where things live

| Path | What's there |
|---|---|
| `src/app/` | Routes. Parenthesised groups — `(shops)`, `(contacts)` — do not appear in the URL |
| `src/app/layout.tsx` | Root layout, metadata, site-wide JSON-LD |
| `src/app/clayspace-brand.scss` | Brand tokens, `.cs-brand` scope |
| `src/app/globals.scss` | Globals + branded components that render outside `.cs-brand` |
| `src/app/robots.ts` · `sitemap.ts` | `/robots.txt`, `/sitemap.xml`. Keep them in step |
| `src/components/clayspace/` | Every Clay Space component |
| `src/components/pages/ClaySpaceHome.tsx` | The composition at `/` |
| `src/lib/structured-data.ts` | schema.org data for the business |
| `src/data/` | Content arrays. **Selected by `id`, never by position** |
| `public/assets/scss/` | Base Sass layer, forwarded through `main.scss` |
| `public/assets/fonts/` | Apfel Grotezk only — SIL OFL, licence alongside |

Two components carry most pages: **`ProgramMain`** for content pages,
**`ClayFormMain`** for request forms.

`ClayNavRail.tsx` is the site's real information architecture — five branches
(Membership, Classes, Shop, Events, About) plus Login / Search / Home and a
pinned cart row. Its `min(100vw, 460px)` width is deliberately matched to Studio
ONE's admin nav; change one and consider the other.

## Known state

Verified clean as of the September 2026 handoff:

- **No dead code — modules or data.** Every module under `src/` is reachable
  from a route entry point, computed from an import graph rather than a name
  heuristic. Data arrays are trimmed to what renders.
- **No type errors.** `typescript.ignoreBuildErrors` is absent from
  `next.config.ts`, so type failures break the build. Keep it that way.
- **No dead internal links.** All 82 distinct internal links across the 41
  exported pages resolve — checked against `out/`, so runtime-built `href`
  values are covered.
- **Font licences resolved.** One self-hosted family, everything else Google
  Fonts. No icon font. See [ATTRIBUTION.md](ATTRIBUTION.md).

## Open, and deliberate — do not "fix" these

- **Nothing can be bought, booked or submitted.** Every form shows a
  confirmation and posts nowhere. This is the launch gate, not a bug.
- **No product detail route.** Six named products link to `/shop`.
  `/shop/[slug]` needs `generateStaticParams` under `output: "export"`.
- **The phone number is `XXX-XXX-XXXX`** on `/contact`, pending a studio line.
  It is deliberately **absent** from the structured data — that is machine-read,
  and a fake number there is worse than none.
- **Café photography is a placeholder.** The menu copy is real.
- **Bench time is 3 hours/week** (owner-confirmed), stated once on `/classes/`.

## The Studio ONE boundary

Studio ONE (`clayspace-admin`) is the system of record — 44 Postgres tables
covering members, enrollments, memberships, tickets, firings and a ledger. This
website will call it over a narrow HTTPS API. It never holds credentials, and
the two never deploy together. That boundary is the security model.

Three things stand between here and that integration, in order: Studio ONE's
member login issues a 30-day session on **an email address alone** and needs
real authentication first; Studio ONE is local-only and has to be deployed; and
its cookie auth is same-origin, with no CORS on any of its 128 routes. All of it
is written up in
[docs/WorkBreakStructure.md §6](docs/WorkBreakStructure.md#6--studio-one-integration--the-launch-gate).
