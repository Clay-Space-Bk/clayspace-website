# Deploying

The site is a static export. There is no server, no runtime dependency and no
environment to configure — a deploy is "put these files behind a CDN".

Production domain: **https://www.clayspacebk.com** (the apex 301-redirects to
`www`).

---

## This repository is the project, not the output

`main` holds the Next.js project. There is no output branch here — `out/` is
gitignored and rebuilt on demand.

**Where the built site is hosted is not yet decided.** The predecessor repo
used two output branches, and if you go that route the distinction below is the
one that bites:

| Approach | Paths | Serves at |
|---|---|---|
| Root-relative — the default build | `/assets/…`, `/_next/…` | a domain root, e.g. `www.clayspacebk.com` |
| Prefixed — `PAGES_BASE_PATH` build | `/<repo>/assets/…` | a GitHub Pages *project* site |

**The two are not interchangeable.** A project site serves from a subpath; a
domain serves from root. Each build is broken in the other's context — assets
404 and the page renders unstyled.

> **Pages will not work from this repository as it stands.** The org is on the
> GitHub Free plan and this repo is private; Pages from a private repo needs
> Pro, Team or Enterprise. Either host the export somewhere else (any static
> bucket or CDN works — it is just files), or make the repo public, or upgrade
> the plan.

## Build for production

```bash
# the dev server must not be running — it shares .next/
rm -rf .next out
npm ci
npm run build
```

`out/` is now the complete site: root-relative paths, ~41 routes.

Check it before shipping:

```bash
npm start          # serves out/ over HTTP on :3008
```

Open it and **open and close the nav rail.** That is the hydration canary — a
broken export still renders a perfect-looking page with a clean console, and
the rail is the first thing to go silent.

Do not open `out/index.html` from the filesystem. Over `file://` the styling
loads but the JavaScript does not, so you get a false negative every time.

## Build for the Pages preview

GitHub Pages serves a project site from `/<repo>/`, so that build needs a base
path. It is opt-in via an environment variable rather than baked into
`next.config.ts`, precisely so the production build stays root-relative:

```bash
rm -rf .next out
PAGES_BASE_PATH=/<repo-name> npm run build
```

`basePath` rewrites Next's own `/_next/` URLs. **It does not rewrite hardcoded
`/assets/` strings**, of which the site has plenty — those need a post-build
pass over `out/`:

```bash
# from the repo root, after the prefixed build
grep -rl '"/assets/' out --include='*.html' --include='*.js' --include='*.css' \
  | xargs sed -i '' 's|"/assets/|"/<repo-name>/assets/|g'
```

> This step is manual today and is the most likely thing to be forgotten.
> Scripting it is a small, worthwhile task.

## Publish

Whatever the target, `out/` **is** the web root — directory structure is URL
structure, so `about/index.html` serves at `/about/`, and moving a directory
changes a live URL.

If you publish to an output branch in a separate checkout:

```bash
rsync -a --delete --exclude='.git' /path/to/clayspace-website/out/ .
touch .nojekyll
git add -A && git commit -m "Rebuild from main@$(git -C /path/to/clayspace-website rev-parse --short HEAD)"
git push
```

Naming the project commit in the message is the only link between published
output and the code that produced it. Keep doing it.

### `.nojekyll`, if you publish to GitHub Pages

Pages runs Jekyll by default, and Jekyll ignores directories whose names begin
with an underscore. That silently drops `_next/` — every stylesheet and every
script in the site. An empty `.nojekyll` at the web root disables it.

## CI

`.github/workflows/ci.yml` runs on push and PR to `main`:

```
npm ci  →  npm run build  →  npm run typecheck  →  npm run lint
```

**Build first, typecheck second.** `next-env.d.ts` is generated by the build and
declares the module types for static image imports (`.png`, `.webp`). Running
`tsc` before the build fails with TS2307 on every image in `src/data`. Don't
"tidy" the order.

`typescript.ignoreBuildErrors` is deliberately absent from `next.config.ts`, so
the build itself typechecks too. Keep it that way.

**Lint is green and enforced.** If you need to suppress a rule, suppress the one
line and say why in a comment — see the cart-hydration effect in
`src/provider/AppProvider.tsx` for the shape of that.

CI does not deploy. Publishing is manual, by the steps above.

## Assets

Photography is capped at **2400px** and saved as **progressive JPEG, quality
82**. The original import carried untouched camera files at 6000×4000 and
several photographs stored as PNG — one was 3.9 MB where 0.35 MB proved
indistinguishable.

- Add photography under ~2400px.
- Save photographs as JPEG, not PNG.
- Exclude `public/assets/img/ceramic-icons/` from any unused-asset sweep — five
  nav icons are assembled at runtime from a template literal and no static
  analysis can see them.

## Why the repository is private

**Not for font licences** — those are resolved, and nothing bundled here blocks
publication. See [../ATTRIBUTION.md](../ATTRIBUTION.md).

It stays private because it is the customer-facing half of an estate whose other
half, Studio ONE, holds member records, payroll bands and a general ledger. The
two repositories are deliberately held at different trust levels, and the
website stays private until it is deployed in earnest.

The website never receives database credentials or auth secrets, and it never
deploys alongside Studio ONE.
